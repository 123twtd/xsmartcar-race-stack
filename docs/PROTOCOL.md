# 上下位机 UART 协议

## 传输格式

当前协议包含两种 ASCII 行帧：

```text
L,near_offset,near_yaw,det_offset_cm\r\n
C,run_is,speed_limit\r\n
```

“三字段 L 帧”指 L 帧携带三个数值字段，不是存在三种不同帧。

## L 帧

| 字段 | 含义 | 单位/约束 |
|---|---|---|
| `near_offset` | 近处横向偏移 | 上位机 IPM/TRK 坐标，按当前标定解释 |
| `near_yaw` | 近处航向偏差 | 按当前上/下位机符号约定解释 |
| `det_offset_cm` | 高级行为附加横向偏置 | cm；未启用时必须显式发送 `0.0` |

旧文档曾只描述 `L,%f,%f`，已经过期。当前上位机构帧和下位机解析均为三个字段。

## C 帧

| 帧 | 语义 |
|---|---|
| `C,1,speed` | 保持运行锁存，目标速度为 `speed` |
| `C,1,0` | 可恢复软暂停：速度归零，保留本地发车锁存 |
| `C,0,0` | 完赛/安全停车：清除运行锁存 |

`C,1,0` 不是清锁停车。使用 `C,0,0` 后，下位机必须再次通过本地按键授权才能发车。

## 本地发车门控

下位机停车状态不解析上位机控制帧。首次启动或锁存被清除后，必须由本地发车按键把 `start_flag` 置为 1。该按键同时承担发车授权和完赛后重新授权职责，串口不能远程绕过。

## 修改协议时必须同步检查

1. 上位机 `build_line_frame()` / `build_control_frame()`；
2. 上位机 UART 发送与退出路径；
3. 下位机 `protocol.c` 解析字段数；
4. `cpu0_main.c` 对 `start_flag`、`speed_limit` 和停车复位的处理；
5. 单位、符号、限幅、默认值和丢帧行为；
6. README、台架日志和串口抓包。
